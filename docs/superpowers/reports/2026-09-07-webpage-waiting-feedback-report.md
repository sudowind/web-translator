# 网页翻译等待反馈修复

## 现场观察与原因

用户反馈在 Chrome 的 MDN Basic HTML syntax 页面点击翻译后没有反应。通过当前浏览器 DOM 与截图只读核实：现场已经存在 220 个成功译文块、0 个失败块，正文有真实中文对照。未刷新、重发或修改用户页面，也没有读取 Provider 凭据。不能反推出最初首批的准确耗时。

代码确认等待阶段没有任何页面级提示；原首批可达 20 块／12,000 字符，视口中的导航也会先于正文进入请求。这些行为会造成“点击没反应”的体验。

## 修复

- 即时页面进度浮层与关闭按钮，独立 Shadow DOM 样式；超过 10 秒显示等待服务提示。
- 完成、失败和无正文均明确反馈，停止清理计时器与面板，迟到结果不回写。
- 可见正文优先，按原文 Range 计算位置；首批最多 3 块／目标 1,800 字符，后续 8 块／目标 6,000 字符，单长块不拆散。
- Popup 打开时轮询更新进度。

- release 网页 E2E：3 项通过，8.3 秒，新增模型响应挂起时的即时进度与关闭验证。使用隔离浏览器、模拟 Provider、授权后技术路径。

## 用户验收

固定目录已更新：`D:\Projects\web-translate\web-translate-plugin\.output\chrome-mv3`。Chrome 内部扩展管理页被浏览器工具拒绝控制（internal tab cannot be claimed）；按项目边界不重复探索。需要用户手动重载原扩展、刷新 MDN 后验证新版进度。现场观察到的真实译文来自用户原请求，不冒充新版人工验收。
