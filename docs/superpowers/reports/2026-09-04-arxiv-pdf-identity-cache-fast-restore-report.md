# arXiv PDF 标识缓存与快速恢复实施报告

日期：2026-09-04  
状态：已完成完整验证

## 实现结果

- arXiv 等价 URL 规范化为稳定论文标识，显式版本隔离；缓存查询不再以完整 PDF 下载和 SHA-256 为前置条件。
- PDF.js 使用 URL 独立加载原文；已有文档模型和译文快照可先于 Canvas 恢复。
- 无版本 URL 只发 HEAD 检查修订，最多等待两秒；网络失败或缺少修订头时保留可用缓存。显式版本不发 HEAD。
- IndexedDB v3 新增源映射与文档来源索引，支持旧 SHA 缓存懒迁移；同源多个旧 hash 时安全视为未命中。
- arXiv 清理入口按来源 URL 解引用已有映射与全部旧索引匹配，覆盖别名尚未写入的首次迁移。公共 PDF 清理后重新解析，认证上传仍要求同意。
- 通用 PDF 仍保留完整字节和哈希校验；公共请求允许标准 HTTP 缓存，认证请求不改变凭据边界。

## 复核与修复

独立复核发现的 Important 已全部修复并聚焦复核关闭，未遗留 Critical/Important：

1. HEAD 超时降级，避免挂起请求无限阻塞恢复。
2. 后台关联校验 arXiv URL、规范键及发送者来源。
3. 旧缓存多候选歧义时不任意复用。
4. 文档、来源映射和后台恢复任务的写入与清理使用代次屏障和逐 hash 写入队列。
5. 清理覆盖已存在别名、首次迁移未写别名、以及旧索引查询迟到返回的时序，阻止旧数据库记录或 LRU 复活。

两项新增竞态回归均先在旧实现中复现失败，再在修复后通过。非法月份及零序号的 Minor 已顺手修复。

完整门禁还发现并修复两项验证基础设施问题：

- 网页翻译 E2E 的模拟接口仍返回普通 JSON，与现有客户端的 SSE 协议不一致。夹具改为两个 `delta.content` 分片及 `[DONE]`，新增 `stream === true` 断言，保留全部翻译、恢复、事件及敏感页面断言；未修改生产逻辑或权限。
- Windows 线程池在复跑时两次无诊断提前退出，详细输出中已运行的断言均通过。相同 61 文件 / 396 测试与 4-worker 上限改用 `forks` 后完整通过；最终将 Windows 默认池设为 `forks`，其他平台仍为 `threads`。PDF.js 的 Node 入口加载原生 Canvas，隔离策略参考 [Vitest 原生模块故障排查](https://vitest.dev/guide/common-errors.html#segfaults-and-native-code-errors)；具体触发模块尚未证实，不把相关性当作确定根因。独立复核确认未降低测试覆盖。

## 验证记录

- 定向服务测试：40 项通过。
- `npm run check`：通过。包含类型检查、61 个测试文件 / 396 项单元测试、WXT 生产构建、扩展产物校验。
- 最终单元测试用时 18.27 秒；DOM 环境初始化累计 20.07 秒（多 worker 累计值，不是墙钟时间），测试体累计 5.55 秒。保留最多 4 个 worker。首轮线程池完整运行曾用时 49.43 秒，其中环境初始化累计 106.74 秒。
- 最终 WXT 构建用时 3.676 秒；生产产物无 Unicode noncharacter、静态 host 权限及静态 content script。
- `npm run test:e2e`：12 项通过、1 项默认关闭的真实 arXiv 在线门禁跳过，无失败，耗时 50.8 秒。使用最终 check 刚生成的生产产物。
- 76 页合成样本首屏可读时间 1,345 ms，挂载译文正文 5 页，首轮 Provider 请求 4 页，缩放帧间隔最大 14 ms。此数据仅用于本地回归，不代表真实网络或真实论文的耗时。
- arXiv 用例在阻塞 PDF.js GET 时已恢复译文，未新增 MinerU/翻译请求；放行 GET 后 Canvas 可见，随后清缓存会创建新的 MinerU 解析任务。

## 验收边界

- E2E 是隔离 Chromium 中的授权测试路径，不冒充真实 action Popup、activeTab 授权或浏览器原生权限弹窗的人工验收。
- 真实 arXiv 在线 76 页样本由 `PDF_ARXIV_FEASIBILITY=1` 显式开启；默认完整 E2E 不访问这一外部网络门禁。
- 无版本 URL 在服务器不给修订头或探测失败时无法严格证明内容未变；此时保留缓存，可手动清理或使用显式版本 URL。
- E2E 挂起 PDF.js 请求后恢复译文并且不新增 Provider 请求；通用整文件读取不进入 arXiv 启动路径另由代码审查确认。尚未单独增加 mock `loadPdfSource` 的完整 `PdfWorkspace` 组件测试，此项为非阻断的测试增强。
- 上次中断前的 E2E 使用旧构建，不能用来判断当前清理重解析路径；本轮仅以新构建的验证结果为准。
