# PDF 单主滚动与逐页配对布局设计

## 背景

当前 PDF 工作台把 PDF、译文和智能体呈现为三个独立面板。PDF 列与译文列各自纵向滚动，并通过滚动意图、可见页观察和同步控制器保持页码一致；译文页内部还存在滚动区域。用户在阅读时会同时遇到页面、PDF 列、译文列、单页译文和智能体等多个滚动上下文，操作负担过高，并容易出现滚动同步抖动。

## 目标

- 主阅读区只使用浏览器页面的一个纵向滚动轴。
- 每一页以语义化“页对”呈现：左侧 PDF 页面，右侧该页译文块。
- PDF 页面与对应译文块严格等高。
- 译文未超过页高时不出现滚动；超出时只在该页译文正文内部滚动。
- 智能体侧栏继续保留，可收起，消息区域独立滚动。
- 保留 PDF 缩放、当前页、页码导航、逐页翻译、失败重试、缓存和 PDF Canvas 可见窗口渲染。

## 非目标

- 本次不改变 MinerU、LLM、缓存、逐页翻译并发和失败诊断逻辑。
- 本次不改变智能体问答上下文和 Provider 配置。
- 本次不实现整页译文无限展开；超出 PDF 页高的内容仍在单页译文块内滚动。
- 本次不自动恢复刷新后的 PDF 接管状态。

## 方案比较

### 方案一：语义化逐页配对流

主阅读组件按页码生成 `.page-pair`，每个单元直接包含 PDF 页面槽位和译文页面。页高来自 PDF 实际渲染尺寸，译文块使用同一高度。该结构让 DOM、视觉顺序和页码语义一致，页定位与响应式布局也最直接。

### 方案二：保留两个列表并依赖高度同步

PDF 与译文继续分别渲染列表，只取消列表滚动。该方案改动较少，但两边仍是不同 DOM 子树，缩放和异步高度变化需要额外同步，容易再次出现页间距偏差。

### 方案三：绝对定位拼接

按 PDF 页面的测量位置定位译文卡片。该方案会增加 ResizeObserver、定位和响应式复杂度，无障碍阅读顺序也不自然。

采用方案一。

## 组件结构

### PdfWorkspace

`PdfWorkspace` 继续负责业务状态、翻译调度、缓存操作、智能体和工具栏。布局调整为：

```text
PDF 工作台
├── sticky 工具栏
├── sticky/普通状态栏
└── 工作区
    ├── 主阅读流
    │   ├── 第 1 页页对：PDF + 译文
    │   ├── 第 2 页页对：PDF + 译文
    │   └── …
    └── sticky 智能体侧栏
```

删除 PDF 列、译文列的引用、用户滚动意图计时器、待恢复译文滚动位置和 `SyncController`。页面级滚动由浏览器处理。

### PairedPageViewer

新增或重构出负责逐页配对渲染的组件。它接收：

- PDF 字节和缩放值；
- 文档模型、译文、页状态、失败和尝试次数；
- 当前 PDF 渲染页；
- 文档就绪、当前页变化、页高变化、重试和复制诊断回调。

组件加载一次 PDF.js 文档并获得真实页数。每个页对包含：

- `.pdf-page-slot[data-pdf-page]`
- `.translation-page[data-translation-page]`

翻译模型尚未返回时，右侧显示同高的解析中占位或上传同意区域，不破坏页对布局。

### PdfPageCanvas

保留 Canvas 渲染、设备像素比、文本覆盖层和渲染取消。PDF 页面仍只渲染当前页前后各 2 页，其余页面使用具有稳定高度的占位符，避免长论文一次性创建所有 Canvas。

### TranslationPage

从现有 `TranslationPane` 中拆出单页展示职责：页头固定在译文卡片内部，正文区域使用 `overflow-y: auto`。卡片外层高度与对应 PDF 页完全一致，正文高度为扣除页头后的剩余空间。

删除译文列表自己的 IntersectionObserver、触摸边界跳页、滚轮边界跳页和键盘边界跳页逻辑。用户滚动到译文块顶部或底部后，继续滚动应自然传递给页面主滚动，不主动跳页。

## 高度与布局

- 页对高度以 PDF 页面槽位的实际高度为唯一来源。
- PDF 缩放变化后重新测量页高，并同步更新当前页对的 CSS 高度。
- 译文块外层使用同一页高，不因翻译完成、失败详情展开或文本增加而撑开页对。
- 译文正文只有在 `scrollHeight > clientHeight` 时出现滚动条；CSS 使用 `overflow-y: auto`，不强制常驻滚动条。
- 每个页对之间使用统一 16px 或 24px 垂直间距，主阅读区使用稳定的 8px 间距体系。
- PDF Canvas 和译文卡片顶部对齐。
- 不使用动画改变高度，避免异步翻译造成布局位移和滚动跳动。

## 滚动、当前页与导航

### 单一主滚动

`body` 恢复纵向滚动，`.pdf-workspace` 使用 `min-height: 100vh` 而不是固定 `height: 100vh`。主阅读流不设置 `overflow-y: auto`。

保留两个必要的嵌套滚动区域：

- 单页译文正文，仅内容溢出时滚动；
- 智能体消息区域，用于长对话。

### 当前页

在页面视口上观察 `.page-pair`，使用现有 `selectDominantPage` 选择可见占比最大的页。观察根为浏览器视口，即 `root: null`。当前页同时驱动：

- 工具栏页码；
- PDF Canvas 可见窗口；
- 智能体当前页上下文；
- 重试当前页操作。

### 页码导航

页码导航直接查找 `[data-page-pair="N"]` 并调用 `scrollIntoView`。考虑 sticky 工具栏高度，页对设置 `scroll-margin-top`，避免页首被遮挡。

URL 初始页只在文档首次就绪时定位一次，不重复抢夺用户滚动位置。

## 智能体侧栏

- 宽屏保持在右侧，使用 `position: sticky`，顶部避让工具栏和状态栏。
- 侧栏最大高度为当前视口扣除顶部偏移，消息区域独立滚动。
- 收起状态只保留可发现的展开控件，不占用过多主阅读宽度。
- 智能体滚动不参与当前 PDF 页判断。
- 窄屏下智能体以可收起区域或覆盖式侧栏呈现，不插入每个页对之间。

## 响应式与无障碍

- 宽屏下页对为 PDF/译文两列，智能体为第三个 sticky 区域。
- 中等宽度下智能体可收起，页对仍保持两列。
- 窄屏下页对改为上下顺序：PDF 在前、对应译文在后；译文仍使用 PDF 页高，保证可读和可触控。
- DOM 阅读顺序按页排列，屏幕阅读器会读完第 N 页 PDF 区域后进入第 N 页译文，再进入下一页。
- 页对和译文区域保留明确的 `aria-label`，失败信息使用 `role="alert"`，动态总进度使用 `aria-live="polite"`。
- 所有按钮保持至少 44×44px 点击区域和可见焦点样式。
- 不隐藏焦点轮廓，不依赖颜色单独表达状态。

## 错误与加载状态

- PDF 字节读取中：主阅读区显示单一加载状态，不制造空滚动面板。
- MinerU 解析中：PDF 页正常显示，每页右侧显示同高的解析中状态。
- 需要上传同意时：同意卡片显示在主阅读区的稳定区域，不改变 PDF 页面自身滚动。
- 翻译失败：失败摘要、重试按钮和默认收起详情仍位于对应页译文块内；详情展开只增加正文内部可滚动内容，不改变页对高度。
- PDF 页面渲染失败：错误文本保留在对应 PDF 页槽位，不影响其他页。

## 测试策略

- 单元测试：页对按页码生成，PDF 与译文共享同一高度，长译文区域具备滚动语义。
- 单元测试：当前页由浏览器视口上的页对观察结果驱动，Canvas 可见窗口仍为前后 2 页。
- 单元测试：页码导航定位页对并考虑 sticky 顶部偏移。
- 单元测试：删除双栏滚动同步后，不再绑定 PDF/译文列的 wheel、touch、pointer 和 keydown 同步事件。
- 组件测试：翻译中、完成、失败和详情展开均不改变页对外层高度。
- E2E：页面只有一个主纵向滚动容器；PDF 和对应译文等高；溢出译文可以内部滚动；主页面滚动能切换当前页；智能体保持 sticky/可收起。
- E2E：滚动过程中 Canvas 数量仍受可见窗口限制，不出现大面积闪烁或重复渲染。
- 响应式检查：宽屏两列页对加智能体，窄屏按 PDF→译文顺序堆叠且无横向滚动。

## 验收标准

- PDF 列和译文列不再拥有独立纵向滚动条。
- 浏览整篇论文主要使用浏览器页面的单一滚动轴。
- 每个 PDF 页面与对应译文块外层高度一致。
- 短译文无内部滚动条，长译文只在该页译文正文内部滚动。
- 页面主滚动稳定更新当前页和 Canvas 渲染窗口。
- 页码导航、当前页重试、失败重试和智能体页码上下文保持正确。
- 智能体侧栏保留、可收起并独立滚动。
- 缓存、MinerU、LLM 翻译和诊断逻辑无回归。
