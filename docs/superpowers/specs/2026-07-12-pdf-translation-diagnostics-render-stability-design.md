# PDF 翻译失败诊断与滚动渲染稳定性设计规格

日期：2026-07-12  
状态：设计已确认，等待书面规格复审

## 1. 目标

解决 PDF 翻译失败只能显示“失败”、无法判断原因的问题，并消除滚动过程中 PDF Canvas 反复卸载和重建造成的闪烁。

本次迭代包含：

1. 保留并展示结构化翻译失败信息。
2. 修复超时、网络错误、HTTP 错误和响应格式错误在传递过程中的错误码丢失。
3. 修复 HTTP 429 与 5xx 的自动重试判定。
4. 稳定 PDF 当前页判断和 Canvas 渲染窗口。
5. 暂不实现流式输出；先使用诊断数据确认实际失败分布。

## 2. 当前问题

### 2.1 错误原因被折叠

Provider 已能产生 `TRANSLATION_TIMEOUT`、`TRANSLATION_JSON_INVALID`、`TRANSLATION_SCHEMA_INVALID`、`TRANSLATION_ID_MISSING`、`TRANSLATION_HTTP_429` 等错误码，但逐页翻译层只识别带 `status` 属性或括号形式的 HTTP 状态，最终把多数错误折叠为 `TRANSLATION_FAILED`。PDF 工作台随后又丢弃异常对象，只保留页面的 `failed` 状态。

结果是用户无法区分超时、限流、服务端错误、网络错误和模型输出格式错误，自动重试也无法可靠识别 429 与 5xx。

### 2.2 滚动触发 Canvas 抖动

左右两栏的可见页观察器都会直接修改 `activePage`。一次 `IntersectionObserver` 回调可能包含多个可见页面，当前页会连续变化。`PdfViewer` 又只渲染当前页及前后各一页，当前页变化会把 Canvas 替换为占位符并重新启动 PDF.js 渲染，形成可见闪烁。

此前加入的用户意图同步只阻止跨栏滚动，没有阻止右侧内容变化修改 PDF 渲染焦点。

## 3. 结构化翻译诊断

### 3.1 数据模型

每个失败页面保存一个脱敏的 `TranslationFailure`：

- `code`：稳定错误码。
- `category`：`timeout`、`rate-limit`、`server`、`network`、`response-format`、`configuration` 或 `unknown`。
- `summary`：中文简短原因。
- `retryable`：是否允许自动或手动重试。
- `attempts`：本次任务实际尝试次数。
- `durationMs`：从首次请求到最终失败的总耗时。
- `httpStatus`：存在时记录 HTTP 状态码。
- `provider`：固定为已脱敏的 Provider 类型，例如 `openai-compatible`。
- `model`：当前翻译模型名称。
- `occurredAt`：失败时间。

不保存或展示 API Key、Authorization Header、完整 Prompt、PDF 原文、完整译文响应或 Provider 原始错误正文。

### 3.2 错误分类

- `TRANSLATION_TIMEOUT`：请求超过翻译超时设置。
- `TRANSLATION_HTTP_429`：限流，可重试。
- `TRANSLATION_HTTP_5XX`：Provider 临时服务错误，可重试。
- `TRANSLATION_NETWORK`：网络连接失败，按有限次数重试。
- `TRANSLATION_JSON_INVALID`：模型输出不是合法 JSON。
- `TRANSLATION_SCHEMA_INVALID`：JSON 不符合译文结构。
- `TRANSLATION_ID_UNKNOWN`、`TRANSLATION_ID_DUPLICATE`、`TRANSLATION_ID_MISSING`：结构化 block ID 不匹配。
- `TRANSLATION_RESPONSE_INVALID`：兼容接口响应缺少标准消息内容。
- 未识别错误统一为 `TRANSLATION_FAILED`，但不能覆盖已有稳定错误码。

### 3.3 重试规则

- HTTP 429、HTTP 5xx 和网络临时错误最多自动尝试 3 次。
- 退避时间继续采用 1 秒、2 秒。
- 超时默认不在同一页立即自动重试，避免连续占用并发槽；最终诊断标记为可手动重试。
- JSON、Schema 和 ID 错误不自动重试，因为相同模型与输入通常会重复失败；允许用户手动重试。
- 页面重试时清除旧诊断并显示当前尝试次数。
- 单页失败不阻塞后续页面顺序翻译。

## 4. 失败信息界面

### 4.1 默认展示

失败页页头显示简短状态，例如：

- `失败：请求超时（30 秒）`
- `失败：接口限流（HTTP 429）`
- `失败：模型返回 JSON 不完整`
- `失败：缺少 2 个译文块`

同时提供“重试本页”和“查看详情”。诊断详情默认收起。

### 4.2 展开详情

展开后显示：错误码、分类、HTTP 状态、模型、耗时、尝试次数、发生时间和是否可重试，并提供“复制诊断信息”。复制内容使用纯文本或 JSON，但必须经过同一脱敏函数生成。

详情区域不能改变译文页的固定外层高度；内容较多时继续使用本页内部滚动。

### 4.3 任务级反馈

顶部状态显示整篇进度：完成页数、翻译中页数、失败页数。失败页数可点击或通过现有“重试失败页”统一处理，但不能自动滚动用户当前阅读位置。

## 5. 错误传递边界

### 5.1 Provider 层

`OpenAiTranslationClient` 保留最具体的稳定错误码和可选 HTTP 状态，不把 JSON、Schema、ID 错误转换成通用网络错误。

### 5.2 逐页翻译层

`translatePage` 直接读取结构化错误码，负责重试计数、总耗时和可重试判断。最终失败抛出包含 `TranslationFailure` 的类型化异常。

### 5.3 PDF 消息层

PDF 消息响应为翻译请求返回安全的结构化失败对象，而不是只有一个字符串。其他 PDF 操作仍沿用现有安全错误字符串，避免无关协议扩张。

### 5.4 工作台状态

工作台把每页状态从单一字符串扩展为状态与可选诊断数据。成功、重试和清缓存时必须移除过期诊断。

## 6. PDF 滚动渲染稳定性

### 6.1 稳定当前页选择

- 每次 `IntersectionObserver` 回调只选择交叉面积最大的一个页面。
- 相同面积时保持现有活动页，避免在页边界来回切换。
- 右侧译文内容回填不得修改 PDF 的渲染活动页。
- 只有左侧 PDF 的用户滚动或显式页码导航可以更新 PDF 渲染活动页。

### 6.2 稳定渲染窗口

- PDF Canvas 保留活动页前后至少各 2 页作为预加载窗口。
- 活动页小幅变化时，已经挂载的相邻 Canvas 保持同一个 React key，不得先替换成占位符再重新挂载。
- 新页面 Canvas 完成首帧前保留尺寸完全相同的占位背景，不能使页面高度变化。
- PDF.js 渲染取消只发生在页面离开稳定预加载窗口、缩放变化或工作台卸载时。

### 6.3 内存边界

不渲染整篇论文的所有 Canvas。稳定窗口最多包含活动页前后各 2 页；离开窗口的页面可以释放 Canvas。该策略优先消除正常逐页滚动闪烁，同时限制长论文内存占用。

## 7. 流式输出决策

本次不启用 `stream: true`。原因：

- 当前首先需要知道失败究竟来自超时、限流还是结构化输出错误。
- 标准 Chat Completions SSE 只提供不完整的 JSON 文本片段，不能直接安全落地单个译文块。
- 当前超时是固定总时限，仅打开流式输出仍会在时限到达时中止。

诊断上线后，如果超时占主要比例，再单独设计“SSE 累积 + 空闲超时 + 最大总时限”；真正逐块显示需要另行设计可验证的 block 流协议。

## 8. 测试策略

### 8.1 单元测试

- 每种 Provider 错误映射到正确 `TranslationFailure`。
- 429、5xx 和网络错误按 3 次上限重试。
- 超时、JSON、Schema 和 ID 错误不自动重试。
- 脱敏诊断不包含 API Key、Prompt、原文和原始响应。
- 同一观察器回调只选交叉面积最大的页面。
- 右侧译文可见页变化不修改 PDF 渲染活动页。
- 稳定渲染窗口在相邻页移动时保留已有 Canvas。

### 8.2 组件测试

- 失败页显示简短原因，详情默认收起。
- 展开后显示脱敏字段并可复制。
- 重试时旧失败信息消失。
- 诊断详情不会撑高译文页外层。

### 8.3 CfT/Playwright

- 模拟超时、429 和非法 JSON，验证对应页面诊断。
- 验证默认详情收起、展开与复制内容。
- 连续滚动多页时，当前及相邻 Canvas 不从 DOM 中反复移除。
- 滚动期间页面高度稳定，PDF 文本与 Canvas 不出现占位符闪回。
- 公开 PDF 与认证 PDF 的 URL 不变、PDF.js 接管和恢复能力继续通过。

## 9. 验收标准

- 任一翻译失败页都能看到明确简短原因。
- 展开详情可以区分超时、限流、服务端错误、网络错误和结构化输出错误。
- 复制诊断不包含任何凭据或论文正文。
- 429、5xx 和临时网络错误实际执行有限自动重试。
- 翻译失败不再全部退化为 `TRANSLATION_FAILED`。
- 正常逐页滚动不再反复卸载当前与相邻 Canvas。
- 右侧译文回填不能改变 PDF 渲染焦点。
- 单元测试、类型检查、生产构建和相关 CfT/Playwright E2E 全部通过。

## 10. 明确不做

- 本次不实现 SSE 流式输出或逐字显示。
- 不记录完整 Provider 响应或 Prompt。
- 不上传诊断信息到后端。
- 不渲染整篇论文的全部 Canvas。
- 不改变 MinerU 解析、翻译缓存键和智能体上下文策略。
