# PDF MinerU 标题层级与独立公式修复设计

## 1. 背景

PDF 工作台已经能够按照 MinerU 区块渲染译文、公式和可选择文本，但真实论文 `1706.03762` 暴露出两个结构问题：

- 章节标题被当作普通段落显示，无法根据原始标题级别形成字号层次。
- 独立成行的公式显示为红色 LaTeX 源码，没有生成 KaTeX 排版。

根据 MinerU 官方 `content_list.json` 说明，当前结构化结果使用 `type: "text"` 配合 `text_level` 区分正文和各级标题；独立公式使用 `type: "equation"`，其 `text` 可以包含外围 `$$ ... $$` 定界符。现有规范化逻辑没有读取 `text_level`，并把包含定界符的完整公式字符串直接交给 KaTeX，因而分别造成标题语义丢失和公式解析失败。

参考资料：<https://opendatalab.github.io/MinerU/reference/output_files/>

## 2. 目标

- 尽可能保留 MinerU 提供的标题、公式和坐标信息，不根据 `3.2.1` 等文本编号猜测结构。
- 将 MinerU `text_level` 保存到内部文档模型，并在译文中形成稳定、可访问的标题层级和字号梯度。
- 将 MinerU 独立公式规范化为 KaTeX 可直接接收的 LaTeX，同时保留原始区块文本和区块身份。
- 让旧文档缓存自动失效并重新解析，同时尽可能复用已有逐页翻译缓存。
- 使用真实 MinerU 输出形态建立单元测试、组件测试和 PDF 工作台视觉回归。

## 3. 非目标

- 本迭代不修改 PDF.js TextLayer 的原生文字框选外观、选区几何或复制行为。
- 不通过 LLM 重新判断标题级别，不根据标题编号、字体大小或正则表达式推断层级。
- 不翻译公式内容，不让翻译模型改写 LaTeX。
- 不改变译文块与 PDF 坐标高亮之间基于 `DocumentBlock.id` 的关联方式。
- 不引入新的后端服务或 MinerU API 调用模式。

## 4. MinerU 语义规范化

### 4.1 标题层级

`normalizeMineru` 按以下规则处理文本区块：

- `type: "text"` 且未提供 `text_level`，或 `text_level` 为 `0`：规范化为 `paragraph`。
- `type: "text"` 且 `text_level` 为正整数：规范化为 `heading`，同时保存标题级别。
- 兼容既有测试和旧格式中的 `type: "title"`：规范化为 `heading`，默认标题级别为 `1`。
- `text_level` 的原始正整数保存为 `headingLevel`；渲染时将 `4` 及以上统一映射为页面内最低标题元素 `h6`，但不丢失模型中的原始层级，也不使用标题文本进行二次猜测。
- `text_level` 若存在但不是非负安全整数，返回不泄露论文内容的 `MINERU_FIELD_INVALID`。

`DocumentBlock` 增加可选的正整数 `headingLevel`。该字段只对 `kind: "heading"` 生效；正文、公式、表格等区块不携带该字段。

### 4.2 独立公式

规范化层新增纯函数，将 MinerU 公式文本转换为 KaTeX 可直接接收的内部 LaTeX：

- 去除字符串首尾空白。
- 若整段由 `$$ ... $$` 包裹，去除外围定界符并保留内部内容。
- 若整段由 `\[ ... \]` 包裹，同样去除外围定界符。
- 没有外围定界符时保持原公式内容。
- 不全局替换反斜杠，不破坏矩阵换行、命令或 `\tag{...}`。
- 规范化后为空的公式视为无效 MinerU 字段，不进入 KaTeX。

`DocumentBlock.text` 继续保留 MinerU 原始公式字符串，便于诊断和上下文构建；`DocumentBlock.latex` 保存去除外围定界符后的规范化结果。公式渲染只读取 `latex`。

## 5. 译文标题与公式渲染

### 5.1 标题语义

单页译文的页眉“第 N 页”已经使用 `h2`。论文区块标题在其下按 MinerU 层级映射：

| MinerU 层级 | HTML 元素 | 建议字号 |
| --- | --- | --- |
| 1 | `h3` | 21px |
| 2 | `h4` | 18px |
| 3 | `h5` | 16.5px |
| 4 及以上 | `h6` | 15.5px |

所有标题保持正常换行，不使用省略号；字号、字重和上下间距共同表达层级。标题内部仍通过 `MarkdownContent` 的行内模式渲染，保留公式和安全链接能力。没有 `headingLevel` 的兼容标题按一级标题处理。

### 5.2 公式语义

`kind: "formula"` 的区块继续使用 KaTeX `displayMode` 渲染，并满足：

- 公式占据独立行，水平方向居中。
- 较宽公式只在自身容器内横向滚动，不撑开译文页面。
- 公式编号由原始 LaTeX 的 `\tag{...}` 保留。
- `throwOnError: false` 保证异常输入不会导致整个页面崩溃；测试必须确保 MinerU 官方形态的合法公式不会进入错误样式。

Markdown 段落中由翻译结果携带的 `$$ ... $$` 仍交给现有 `remark-math` 与 `rehype-katex` 处理，不复用独立公式的去定界逻辑。

## 6. 缓存兼容

文档模型增加数值字段 `schemaVersion`，当前结构版本常量命名为 `DOCUMENT_SCHEMA_VERSION`。新规范化结果写入当前版本；读取缓存时：

- 版本匹配：直接复用文档缓存。
- 版本缺失或不匹配：忽略旧文档模型，重新从 MinerU 结果生成并覆盖缓存。
- 逐页翻译缓存键不变。区块顺序和 `DocumentBlock.id` 不变时，重新解析后继续复用既有翻译，避免整篇论文再次请求 LLM。
- 用户主动执行“清理本文缓存”时，仍按既有行为清理文档、翻译、任务和阅读记录。

如果重新解析时 MinerU 不可用，应展示现有解析失败诊断，不返回已知缺少标题层级和公式规范化的旧模型冒充成功结果。

## 7. 测试策略

### 7.1 规范化测试

使用接近 MinerU 官方文档的输入验证：

- `type: "text", text_level: 0` 生成正文。
- `text_level: 1/2/3` 生成对应 `headingLevel`。
- 旧 `type: "title"` 仍生成一级标题。
- 非法 `text_level` 返回脱敏错误。
- `equation.text` 为多行 `$$ ... $$` 时，`text` 保留原值，`latex` 只包含内部公式。
- `\[ ... \]`、无定界符公式和带 `\tag{1}` 公式均正确规范化。

### 7.2 组件测试

- 标题级别分别生成 `h3`、`h4`、`h5`、`h6`。
- 公式 HTML 包含 KaTeX 展示结构，不包含 `katex-error`，并保留编号。
- 公式过宽时仍受 `.translation-formula` 容器约束。
- 原有 Markdown 安全、列表、表格和区块联动测试继续通过。

### 7.3 缓存与工作台测试

- 当前结构版本文档直接命中缓存。
- 旧结构版本文档触发 MinerU 重新解析并覆盖缓存。
- 重新解析后相同页码和区块 ID 仍能命中既有翻译缓存。
- E2E 固定数据改为 MinerU 官方 `text + text_level` 和带 `$$` 的 `equation` 形态。
- 固定视口截图验证标题字号层级、块级公式居中、公式编号及页面无横向溢出。

## 8. 验收标准

- 在 `https://arxiv.org/pdf/1706.03762` 的译文中，`3.2.1`、`3.2.2` 等章节标题与正文有明确字号和字重差异。
- 截图中的 Attention 公式以 KaTeX 行间公式显示，不再出现红色 `$$ ... $$` 源码。
- 公式编号 `(1)` 正常保留，较宽公式不会撑宽整页。
- 已解析过的旧论文在重新加载后自动刷新文档结构，不要求用户手动清理缓存；已有译文在区块 ID 不变时继续复用。
- PDF 原生文字框选行为和视觉效果保持本迭代开始前的状态。
- 定向单元测试、TypeScript 检查、完整 `npm run check` 与 PDF 工作台 E2E 全部通过。
