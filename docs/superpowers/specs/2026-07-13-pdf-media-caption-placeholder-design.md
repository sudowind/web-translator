# PDF 表格与图片标题翻译及占位渲染设计

## 背景与问题

当前逐页翻译会把表格的 `table_body` HTML 作为翻译输入，并把返回结果渲染为 Markdown 表格。历史翻译缓存只校验数组元素结构，不校验当前页所有应翻译区块是否齐全，因此旧缓存缺少表格结果时，页面仍会被标记为完成，而表格区块继续显示“翻译中”。图片虽然不进入翻译请求，但右侧仍缺少与表格一致的明确占位语义。

本次修复把表格和图片统一视为“媒体区块”：不翻译、不渲染媒体本体，只翻译 MinerU 提供的标题，并在右侧显示可与左侧 PDF 高亮联动的占位卡片。

## 目标

- 表格 HTML、图片路径、图片 OCR 正文不得发送给 LLM。
- 只翻译 MinerU `table_caption` 与 `image_caption` 提供的标题。
- 表格和图片在译文区只显示占位卡片及标题状态，不渲染本体。
- 没有标题的媒体区块不调用 LLM，稳定显示“无标题”。
- 翻译缓存必须与当前页应翻译区块精确匹配，不能因缺块而永久显示“翻译中”。
- 只淘汰受媒体翻译语义变化影响的页面缓存；普通纯文本页面继续复用原缓存。
- 保持区块 ID、页内顺序、坐标、高亮、固定状态、PDF 文本框选和智能体侧栏行为不变。

## 非目标

- 不在译文区还原表格布局、图片缩略图或图片 OCR 内容。
- 不识别或翻译图表内部文字。
- 不根据 HTML、文件名、OCR 文本或 LLM 输出猜测标题。
- 不改变左侧 PDF.js 的渲染与文本选择实现。
- 不重构 MinerU 独立 `table_caption`、`image_caption` 类型区块的既有顺序语义。

## 数据模型

`DocumentBlock` 增加可选字段：

```ts
caption?: string;
```

文档结构版本从 `2` 升级为 `3`。MinerU 规范化规则如下：

- `table_caption` 数组以换行连接后写入表格区块的 `caption`。
- `image_caption` 数组以换行连接后写入图片区块的 `caption`。
- 空数组、全空白标题或未提供标题时不写入 `caption`。
- `text` 继续保留当前上游文本兼容语义，但媒体翻译和右侧媒体展示不得读取它来替代 `caption`。
- `html`、`resourceUrl` 与 `polygon` 继续保留，供其他内部能力和左侧联动使用，但不得进入媒体标题翻译请求。
- 区块 ID 的生成方式不变，旧文档缓存会因结构版本升级自动重新解析。

## 翻译请求

逐页翻译统一通过一个共享函数生成应翻译区块：

- 标题、正文、列表、普通 caption、脚注和其他文本沿用当前文本输入。
- 表格和图片仅在 `caption` 为非空字符串时进入请求，请求 `text` 等于 `caption`，ID 仍为媒体区块 ID。
- 无 caption 的表格和图片不进入请求。
- 公式仍不翻译。
- 表格 `html`、图片 `resourceUrl` 和媒体 `text` 不得作为回退输入发送。

Provider 仍必须为请求中的每个 ID 精确返回一次结果；缺失、重复或未知 ID 沿用现有结构化错误。

## 缓存策略

翻译缓存命中必须同时满足：

- 缓存值是合法的 `{ id, text }[]`。
- ID 无重复。
- ID 集合与当前页共享翻译区块生成函数产出的 ID 集合完全一致。

不完整或包含额外 ID 的缓存视为失效，重新翻译整页并覆盖同一缓存记录。

为避免把历史“完整表格 Markdown”误当成新 caption 译文：

- 页面含 `table` 或 `figure` 区块时使用翻译缓存 schema `2`。
- 页面不含媒体区块时继续使用 schema `1`，保留既有纯文本页面缓存。

这项升级只影响含媒体的页面，不清空整篇论文缓存。

## 译文区渲染

表格和图片均渲染为媒体占位卡片：

- 卡片标签分别为“表格”和“图片”。
- 有 caption 且译文存在时，以安全的行内 Markdown 渲染译文标题。
- 有 caption 且正在翻译时显示“标题翻译中…”。
- 有 caption 且页面失败时显示“标题翻译失败”。
- 有 caption、页面已完成但结果缺失时显示“标题译文缺失”，不得继续显示“翻译中”。
- 无 caption 时始终显示“无标题”，不受页面翻译状态影响。

占位卡片继续使用媒体区块原 ID 与 polygon，保留悬停预览、点击固定和左侧高亮。占位卡片不创建新的纵向滚动容器。

## 错误处理

- 历史缓存缺少表格、图片标题或其他应翻译 ID：忽略缓存，重新翻译整页。
- 重新翻译失败：页面进入现有失败状态并显示可展开诊断，媒体卡片显示“标题翻译失败”。
- 页面状态为完成但运行时仍缺失媒体标题译文：卡片显示“标题译文缺失”，作为防御性提示。
- 无 caption：不是错误，不请求 Provider，也不产生失败状态。

## 测试与验收

### 单元测试

- MinerU 规范化正确写入表格与图片 `caption`，拒绝非法 caption 数组，并忽略全空白 caption。
- 逐页翻译只发送媒体 caption，绝不发送表格 HTML、图片路径或媒体正文。
- 无 caption 的表格和图片不进入翻译请求。
- 完整缓存直接复用；缺少媒体 caption ID、包含额外旧表格 ID或重复 ID的缓存会重新翻译并覆盖。
- 纯文本页面继续使用缓存 schema `1`，含媒体页面使用 schema `2`。
- 表格和图片只渲染占位卡片；完成状态缺失结果时不出现“翻译中”。

### 端到端测试

- 固定 MinerU 数据同时包含有标题与无标题的表格、图片。
- 断言请求正文不含 `table_body`、图片路径和媒体正文，只含 caption。
- 断言右侧没有实际表格和图片元素，存在对应占位卡片及翻译标题/“无标题”。
- 断言媒体占位卡片仍能触发左侧区块高亮。
- 更新受影响的 Windows 视觉快照并人工检查占位层级、标题排版和状态文案。

## 安全与兼容性

- 不打印或读取本地 Provider 凭证。
- 不扩大扩展权限和网络访问范围。
- HTML 继续只作为内部模型数据保存，不在右侧注入 DOM，也不进入 LLM 请求。
- 旧文档通过 schema `3` 自动重新解析；普通页面译文缓存复用，媒体页面按 schema `2` 定向更新。
