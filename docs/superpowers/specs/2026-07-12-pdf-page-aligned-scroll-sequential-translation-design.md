# PDF 逐页等高滚动与顺序翻译设计规格

日期：2026-07-12  
状态：设计已确认，等待书面规格复审

## 1. 目标

调整 PDF 工作台的逐页阅读体验，解决译文回填导致滚动位置跳动或左右栏互相牵引的问题，并把翻译调度改为从第一页开始的固定顺序。

本次变更包含两个不可分割的目标：

1. 左侧每个 PDF 页面与右侧对应译文页保持等高，长译文只在本页内部滚动，不撑高外层页面。
2. 翻译从第一页开始按页码顺序派发，不再根据当前阅读页调整优先级。

本规格覆盖总体设计中“当前页优先翻译”和旧版左右同步规则；未被本规格修改的 PDF 接管、URL 不变、解析、缓存和智能体要求继续有效。

## 2. 已确认交互

### 2.1 逐页等高

- 每个左侧 PDF 页面与右侧相同页码的译文区域一一对应。
- 右侧译文页的外层高度采用左侧 PDF 页面的实际渲染高度，而不是固定常量或译文内容高度。
- PDF 缩放、窗口尺寸或栏宽变化导致页面高度变化时，右侧对应页同步更新高度。
- 译文较短时保留空白，不能压缩该页高度。
- 译文较长时，页头保持可见，正文在该页内部独立滚动，不能撑高外层译文页。
- 译文从占位内容替换为最终结果时，外层页高和外层滚动位置保持不变。

### 2.2 页内滚动与跨页滚动

- 鼠标位于长译文正文内时，滚轮优先滚动当前页的内部正文。
- 当前页正文滚动到底后继续向下滚动，自动把外层译文流带到下一页。
- 当前页正文滚动到顶部后继续向上滚动，自动把外层译文流带到上一页。
- 跨页后，左右栏按相同页码对齐；新进入页面的页内译文从顶部开始。
- 页内滚动不改变左侧 PDF 的页内进度，也不反向拖动 PDF。

### 2.3 用户意图驱动的左右联动

- 只有明确的用户滚动、键盘翻页、触摸操作或页码跳转可以驱动另一栏。
- 翻译结果回填、占位内容变化、`ResizeObserver`、`IntersectionObserver` 和程序化滚动不得成为新的联动源。
- 用户滚动左侧 PDF 外层时，右侧外层译文流对齐到相同页码和页内进度。
- 用户滚动右侧外层译文流跨页时，左侧 PDF 对齐到相同页码；右侧页内正文滚动不驱动左侧。
- 智能体页码引用等显式导航命令仍同时跳转左右两栏。
- 程序化同步期间必须抑制回环，不能产生左右栏反复抢夺滚动位置。

## 3. 顺序翻译调度

- MinerU 完成解析后，调度器固定从第 1 页开始派发翻译请求。
- 并发数维持为 2，因此首批派发第 1、2 页，释放并发槽后继续派发第 3、4、5 页。
- “顺序”指请求派发顺序严格按页码递增；不同请求的完成顺序可以因网络耗时不同而变化。
- 当前阅读页变化不得重排队列，也不得取消已经发出的翻译请求。
- 单页失败后标记失败并继续派发后续页面，不能阻塞整篇论文。
- “重试当前页”和“重试失败页”仍保留；只有状态为失败的页面可以进入重试队列，重试请求可以插入空闲并发槽，但不能永久阻塞尚未翻译页面。
- 逐页译文缓存和缓存键保持不变，缓存命中不调用 LLM，并立即释放当前调度槽。

## 4. 组件边界

### 4.1 PDF 页面尺寸上报

`PdfViewer` 负责测量每个实际页面槽的渲染高度，并以页码到高度的映射上报给工作台。测量覆盖初次渲染、缩放和容器宽度变化，且只在高度实际变化时更新状态。

### 4.2 译文页布局

`TranslationPane` 接收页高映射。每个译文页由固定高度的外层和可滚动正文组成：

- 外层负责与 PDF 页面逐页对齐。
- 页头显示页码与翻译状态。
- 正文负责本页长内容滚动。
- 页内正文到达边界时，把剩余滚轮意图交给外层跨页导航。

### 4.3 同步控制器

同步控制器增加“用户意图”和“程序化同步”边界：

- 用户输入开始时登记当前驱动栏。
- 只有驱动栏随后产生的外层可见页变化才允许同步另一栏。
- 程序化滚动产生的观察器回调被忽略。
- 用户停止操作后清除短期驱动状态，不让后续内容回填继续沿用旧意图。

### 4.4 翻译调度器

`PageScheduler` 移除基于 `activePage` 的距离排序，内部只维护下一个待派发页码、进行中页、已完成页和失败页。阅读页状态继续供工具栏、同步和智能体使用，但不再传入翻译调度器。

## 5. 异常与边界处理

- MinerU 尚未返回文档模型时，右栏继续显示解析状态，不创建虚假的译文页高度。
- 某页高度尚未测得时，使用当前 PDF 页面占位高度；测量完成后再校准，不允许跳到论文底部。
- PDF 页面缩放后保持当前页码，不要求保持缩放前的精确像素位置。
- 无文本页面、纯公式页或纯图片页仍创建等高译文页，并显示已有结构化内容。
- 译文页内部滚动条与外层滚动条必须视觉可辨，不得形成无法离开的滚动陷阱。
- 触摸设备和键盘操作遵循与滚轮相同的边界转交规则。

## 6. 测试策略

### 6.1 单元测试

- 调度器在当前阅读页变化后仍按 `1, 2, 3, 4...` 顺序派发。
- 并发为 2 时只同时派发两个页面，完成或失败后继续下一页。
- 同步控制器忽略没有用户意图的可见页变化。
- 程序化同步不会回环。
- 页内滚动未到边界时不触发跨页，到达上下边界后才转交外层。

### 6.2 组件测试

- 译文页外层采用对应 PDF 页高。
- 长译文正文出现内部滚动，外层高度不随译文增长。
- 翻译结果回填前后，外层译文流的 `scrollTop` 保持稳定。

### 6.3 CfT/Playwright 端到端测试

- 在译文持续回填期间，用户停留页不会自动滚到论文底部。
- 左右同页区域的外层高度相等。
- 长译文页可以内部滚动，并在边界继续滚动时进入相邻页。
- 打开带 `#page=N` 的 PDF 仍定位到指定阅读页，但首个翻译请求固定为第 1 页，第二个为第 2 页。
- 公开 PDF 与认证 PDF 两条路径均保持 URL 不变、PDF.js 重渲染和关闭恢复能力。

## 7. 验收标准

- 翻译回填不能改变用户当前外层阅读位置，不能把页面锁定或拉向底部。
- 任意页的右侧外层译文区域与左侧 PDF 页面等高。
- 超长译文只在对应页内部滚动，滚动到边界后能够自然进入相邻页。
- 左右联动仅由用户操作或显式导航触发，内容更新不能触发联动。
- 翻译请求派发顺序从第 1 页开始严格递增，不受当前阅读页影响。
- 单元测试、类型检查、生产构建和相关 CfT/Playwright E2E 全部通过。

## 8. 明确不做

- 不改变 MinerU 解析协议、LLM 翻译 Prompt、缓存结构或智能体上下文策略。
- 不把翻译并发数改为用户可配置项。
- 不实现段落坐标级对齐；本次只保证页级等高和页内独立滚动。
- 不在本次迭代加入可拖动栏宽或新的视觉主题。
